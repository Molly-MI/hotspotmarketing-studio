# 热点营销工作台 · HotSpot Studio

![状态](https://img.shields.io/badge/%E7%8A%B6%E6%80%81-%E5%8E%9F%E5%9E%8B-blue) ![依赖](https://img.shields.io/badge/%E4%BE%9D%E8%B5%96-%E9%9B%B6%E7%AC%AC%E4%B8%89%E6%96%B9%E5%BA%93-brightgreen) ![模型](https://img.shields.io/badge/%E5%A4%A7%E6%A8%A1%E5%9E%8B-DeepSeek%20%2F%20OpenAI%20%E5%85%BC%E5%AE%B9-orange)

电商媒体热点营销工作台:从**真实热点抓取 → 商品智能匹配 → 大模型文案生成 → 合规审核发布**的全流程闭环,配套一整套后台(提示词工程、商品库、效果评测、数据看板)。

> **这是一个原型**,用来验证"热点借势营销能不能自动化"这条链路。热点抓取和大模型调用都是真的,发布环节是模拟的。
> 全程零第三方依赖 —— 纯原生 JS + Node 内置模块,克隆下来双击就能看,不需要 `npm install`。

**几个可能有参考价值的点**:借势风险识别(灾难/疫情/战争类热点禁止拿来营销)、中文标题去重(二元组相似度,不引分词库)、合规自愈(校验不过时带着失败原因让模型返工)、以及一套完整的提示词 A/B 评测。[`VIBE-PROMPTS.md`](VIBE-PROMPTS.md) 把整个项目拆成了 14 段可复用的提示词。

## 快速开始

**方式一:直接双击 `index.html`** —— 零依赖,使用内置演示数据与本地 Mock 文案,离线可演示。

**方式二:完整能力(真实抓取 + 真实大模型)**

```bash
cp .env.example .env   # 在 .env 里填入 DEEPSEEK_API_KEY
```

```bash
node server.js
```

打开 http://localhost:8787 ,页面检测到服务端已配置密钥后会自动切换到真实大模型。

> DeepSeek 密钥在 https://platform.deepseek.com/api_keys 创建。任何 OpenAI 兼容接口(Kimi、通义千问、vLLM、Ollama)都可以在「模型设置」里换 Base URL 直接用。

## 无服务器部署：Cloudflare Worker + KV

这一方式不需要保留 VPS、Nginx、Docker、HTTPS 证书或 SSH。静态页面由 Worker 的 Assets 提供，`/api/*` 在 Cloudflare Worker 中运行；提示词、商品、数据集、抓取源、评测记录和运行事件存入 Cloudflare KV。

### 一次性准备

1. 在 Cloudflare 控制台依次打开 **存储和数据库 → KV → 创建命名空间**，创建 `hotspot-marketing-studio`。
2. 复制该命名空间的 ID，替换 [`wrangler.jsonc`](wrangler.jsonc) 里的 `REPLACE_WITH_YOUR_KV_NAMESPACE_ID`，然后提交该修改。不要填写 KV 名称，必须是 Namespace ID。
3. 将仓库导入 Cloudflare 的 **Workers 和 Pages**，按 Worker 项目部署。仓库已有 `wrangler.jsonc`、入口 `worker/worker.mjs` 和静态目录 `dist/`；如果控制台要求填写部署命令，使用 `npx wrangler deploy`，无需构建命令。
4. 首次部署成功后，进入该 Worker 的 **设置 → 变量和机密**，新建加密变量 `DEEPSEEK_API_KEY`。也可选填 `LLM_BASE_URL`、`LLM_MODEL`。密钥只在 Worker 运行环境中读取，`/api/config` 只会返回是否存在密钥。
5. 在 Worker 的 **设置 → 域和路由** 添加自定义域名 `hotspot.hielise.tech`。该名称当前若仍存在指向旧阿里云服务器的 `A` 记录，先删除该旧记录，再让 Cloudflare 为 Worker 创建自定义域名路由；否则请求仍可能被送到旧源站。

部署完成后，用下列地址验收：

```text
https://hotspot.hielise.tech/
https://hotspot.hielise.tech/api/config
```

第二个地址应返回 JSON，且 `hasServerKey` 为 `true`（已经配置 `DEEPSEEK_API_KEY` 时）。如果是 `false`，页面仍可演示，但不能在不输入浏览器临时 Key 的情况下调用模型。

### 运行边界

- KV 是最终一致存储，适合当前单管理员的配置和轻量事件记录；不是事务数据库。
- 新闻抓取仍依赖目标站点的公开响应。单个源失败会在 `/api/news` 的 `sources` 字段中报告，不会让整个页面失效。
- Node `server.js` 保留为本地开发/离线演示入口，但公开生产流量不再经过它。

## 工作台的两种模式

**✋ 手工模式** —— 经典 5 步:新闻抓取 → 建议匹配商品 → 商品库筛选 → 创作文案(多版本并发流式生成)→ 审核并发送。

**⚡ 自动模式** —— 一键跑完整条流水线:抓取实时热榜 → 按热度阈值/匹配度筛选 → 自动选品 → 生成文案 → 合规校验 → 倒计时后自动发送,并把每一条的处理结果记进「自动发送清单」。

自动模式有三条**不可关闭**的安全底线:

1. 灾难 / 疫情 / 战争 / 犯罪类风险热点绝不自动发送(抓取时即标记拦截)
2. 文案出现广告法违禁词或编造价格时,自动转人工复核而非发送
3. 每条发送前有可取消的倒计时

## 热点去重

同一个热点会被多个源反复报道,也可能昨天已经发过,自动模式必须能认出来。去重逻辑在 `dedupe.js`,前后端共用同一套算法:

- **相似度算法**:中文标题没有词边界,用「二元组 + Dice 系数」,不依赖分词库。一方完整包含另一方时(且短的一方 ≥6 字)给 0.82 兜底。实测同源标题 0.62~0.90,不同事件 0.00~0.25,默认阈值 0.55 落在中间空档。
- **同批次跨源聚类**(`news.js` 抓取时):微博和百度报同一件事只保留名次最靠前的一条,卡片上显示「N 源在报」。此前用的是"前 18 字精确匹配",措辞稍变就漏。
- **跨轮次去重**(`PublishIndex`):从事件日志载入历史发布记录,默认 72 小时窗口内判重。窗口与阈值可在自动模式配置里调。

两种模式的处理不同:自动模式直接跳过并在清单里记明原因(`重复发布拦截:6h 前已发过「…」(相似度 0.75,去重窗口 72h)`);手工模式只在卡片上标「🔁 6h 前发过」并弹提示,**不阻断** —— 运营可能是有意二次借势。

已知限制:同一事件的不同角度(如「小米新车预售价 29.99 万」与「小米新车像在卖房」)相似度仅 0.25,会被当作两个热点。调低阈值能覆盖但会带来误杀,当前选择宁可漏判。

## 合规自愈

文案生成后会先过一遍发布前的规则校验(字数、话题标签、emoji、违禁词、价格幻觉、互动引导、markdown 残留、商品提及)。没通过时,系统会把**具体失败原因**回喂给模型让它自己改一版,改完重新校验,只有改好了才采纳 —— 改差了自动保留上一版,改不好才转人工。

- 手工模式:输出面板底部显示合规状态条与逐项失败原因,点「一键修正」触发
- 自动模式:自动修正(轮数可配,默认 2 轮),硬性项仍不过才转人工复核
- 修正用的提示词在后台「提示词模板 → 合规修正提示词」里可编辑,两条路径共用

实测效果:一条超字数 235 字、含「全网最低/最好」违禁词、编造 ¥9.9 价格的文案(规则分 21.4),一轮修正后规则分 100,字数 209,价格全部回到商品库的真实数字。

清单里待复核的条目可一键「转到手工审核」,带着热点与商品上下文直接落到 Step 5。

## 真实热点抓取

服务端代抓(不受浏览器跨域限制),内置微博热搜、百度热搜、今日头条热榜,外加任意 RSS / Atom 源。抓取源在 `admin.html` 的「抓取源配置」里增删与测试,结果服务端缓存 60 秒。

抓到的每条新闻都会做**借势风险识别**并附在卡片上:灾难/疫情/战争/犯罪 → 禁止借势(工作台阻止选用);时政/社会争议 → 需人工判断。

热点与商品的匹配走 `data.js` 里的**场景关键词匹配算法**:先用热点文本命中消费场景,再用场景去匹配商品卖点。内置了 18 个场景,覆盖实物品类(高温消暑 / 运动健身 / 户外露营 / 穿搭颜值 / 国风文创 …)与零食品类(追剧综艺 / 办公加班 / 观赛聚会 / 节日送礼 / 减脂控糖 / 儿童零食 / 熬夜夜宵 / 出行囤货 / 寒潮暖食 / 消暑冷饮)。

匹配度是**绝对分**(至少完整命中一个场景才算匹配),匹配不上会明确显示"没有可借势的消费场景"——时政、财经类热点通常如此,这是预期行为。换商品品类时,在 `SCENES` 里补对应场景关键词即可。

> 商品库默认是 100 个零食商品(10 个品类各 10 款),在 `products.json` 里,可在「商品库管理」页增删改或整体导入替换。

> ⚠️ 合规提示:热榜接口为站点公开数据,仅供原型演示。生产环境请改用官方开放平台(如微博开放平台)或商业舆情 API,并遵守目标站点的 robots.txt 与服务条款。

## 效果评测(Eval)

营销文案没有标准答案,所以评测做成**三层 + 回归对比**:

1. **规则校验层**(不花 token、确定性强):字数、话题标签、emoji 数量、**广告法违禁词**、**价格幻觉**(文案里的价格必须来自商品库)、互动引导、markdown 残留、商品提及
2. **LLM 评委层**:热点关联度 / 卖点覆盖度 / 传播吸引力 / 语气自然度,各 1~5 分(低温调用保证打分稳定)
3. **人工标注**:👍/👎 + 备注,用来校准评委

改完提示词回来跑同一个数据集,在「历史与对比」里选两次运行做 **A/B**:指标 delta、逐用例分数变化、**高亮这次改动导致变差的用例**,并标出两次用的是不是同一版提示词。

## 目录结构

```
index.html      工作台(手工 5 步 + 自动流水线 + 模型设置)
dashboard.html  数据看板        admin.html   提示词与模型配置
products.html   商品库管理      eval.html    效果评测台
data.js         数据层 + 热点→商品匹配算法 + 商品库读取
prompts.js      提示词模板中心(各页面共用)
llm.js          大模型接入层(OpenAI 协议 + SSE 流式)
eval.js         评测引擎(规则/评委/并发池/运行记录)
news.js         服务端真实抓取(热榜 + RSS + 风险识别)
server.js       本地服务:静态托管 + 各类 API(零第三方依赖)
```

运行时生成的数据文件(已在 `.gitignore` 中排除,克隆后首次运行自动生成,`.bak` 为上一版备份):
`prompts.json` 提示词 · `products.json` 商品库 · `datasets.json` 评测数据集 · `sources.json` 抓取源 · `evals/*.json` 评测运行记录 · `events.jsonl` 运行事件流水(看板数据源)

## 接口

| 接口 | 说明 |
|---|---|
| `POST /api/llm` | 大模型代理,附加服务端密钥转发,支持 SSE 流式 |
| `GET /api/news` | 真实抓取聚合结果(带风险标记);`?force=1` 跳过缓存 |
| `GET/PUT /api/news/sources` | 抓取源配置 |
| `GET/PUT /api/prompts` | 提示词模板 |
| `GET/PUT /api/products` | 商品库 |
| `GET/PUT /api/datasets` | 评测数据集 |
| `GET/POST /api/eval-runs` | 评测运行记录(列表 / 单条 / 保存) |
| `GET/POST/DELETE /api/events` | 运行事件流水 |
| `GET /api/config` | 服务端能力探测(是否配置密钥等) |

## 安全提示

- `.env` 不要提交到代码仓库
- 页面「模型设置」里填的密钥保存在浏览器 localStorage,仅供 Demo;生产环境请用服务端代理模式
- `server.js` 只监听 `127.0.0.1`,不要直接暴露到公网
- Step 5 的「一键发送」与自动模式的发送均为**模拟**,接入微博开放平台 API 后才会真实发布
- `server.js` **没有任何鉴权**,仅供本机单人使用;要给多人用必须先加登录与审计
- 配置存在 JSON 文件里,并发写入可能丢数据;上量请换数据库
